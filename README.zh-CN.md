# STRATA（中文摘要）

**你的编码 Agent 总是重复犯同样的错。这个方法是用来止住它的 ——
做法是把规则挂在「一类文件」上，而不是挂在单个文件上。**

## 问题

Agent 在真实仓库里会以三种可预测的方式失败：

| 失败 | 表现 |
|---|---|
**不知道去哪找** | 读错文件，漏掉关键的那个 |
**破坏了不知道的东西** | 改了函数，漏掉两个调用方 |
**重复你已经纠正过的错误** | 你写了「不要做 X」，下周它又做 X |

常见的应对 —— 更长的上下文、更好的检索、更自主的 Agent —— **都不解决第三种**。
用散文告诉 Agent「不要做 X」，和让 X **根本不可能发生**，是两件事。

## 核心想法（90 秒）

每个代码单元有一个**坐标**：架构层 + 业务域。

```
⟨ scripts, config ⟩    ⟨ lib, rendering ⟩    ⟨ api, auth ⟩
```

这个坐标对就是一个**面（face）**。约束挂在**面**上，而不是文件上：

```yaml
- id: no-shell-exec
  scope: scripts/*        # ← 面：scripts/ 下的一切
  check: "! grep -rn 'execSync' src/scripts"
```

关键在于：

> **你在 `scripts/` 下新增一个文件时，这条规则已经覆盖它了。**
> **你不需要写任何新规则。**

逐文件的做法下，每新增一个文件就至少要多一条规则；
面锚定下，规则只在出现**新的面**时增长 —— 而面是有限的小集合（`|层| × |域|`）。

**整个方法就这一句**：

> **把约束锚定在坐标类上，而不是文件上 —— 于是新文件继承规则，而不是产生新规则。**

## 30 秒试一下

先测这个方法对你**是否可能有用**。纯静态扫描，不需要 Agent、不需要日志、不需要 LLM：

```bash
node scripts/measure.mjs --root /path/to/your/repo
```

它会打印 **κ** —— 与至少一个其他文件共享同一个面的文件比例：

| κ | 含义 |
|---|---|
**≥ 0.5** | 方法适用，继续看快速上手 |
**0.3 – 0.5** | 部分适用，收益只在密集区域 |
**< 0.3** | **停。** 文件差异太大，面已退化为文件。只能单独用判决层 |

## 落地顺序（**顺序不能反**）

```
S 点（每文件一行）→ T 线（related 字段）→ R 面（层 × 域字典）
                                          ↓
                                    A 锚定（约束挂面上）
                                          ↓
                                    V 判决（check 命令）
```

**先把字典定义出来，再写条目。** 反过来（先写条目后补字典）是最常见的毁掉方法的方式：
面会退化成逐文件标签，收益全部消失。

## 状态：**这是可用的方法，不是已验证的理论**

必须直说，因为它影响你该信到什么程度：

- **核心主张（面锚定把边缘规则成本降到 0）是推导出来的，尚未被检验。**
  设计的实验（E1–E4）**一个都没做**。
- 现有的是**一个起源案例**：单开发者、单代码库。其中 **κ = 0.68**；
  一条已被文档禁止的**代码形态**，在可执行检查器出现前，**26 天内被模式匹配到 21 次**。
**这 21 次是"嫌疑"，不是确认的违规** —— 启发式检测器会高估（模板注释里成对的反引号
其实不构成语法错误）。**真实违规数 ≤ 21，未测。**
- **n = 1。** 那只是带数字的轶事，不是证据 —— 它说明方法**被用过一次**，
  不说明它**有效**。
- 上述测量来自**对真实开发过程的观察**。观察数据**不能确立因果**，
  且该案例本身有缺陷：git 历史被压缩、可执行检查器引入过晚，无法做前后对照。

**对你的实际含义**：**κ 的测量是真的，你今天就能跑**；
**收益是假设。** 你若采用它，你就是在检验它。

## 什么时候不要用

- **文件少于约 30 个，或很少改动** —— 索引的成本大于收益。
- **κ < 0.3** —— 见上。
- **无法运行检查命令** —— 没有判决层就只剩索引，仍有用但弱得多。
- **你需要形式化保证** —— 这是实用约定，不是验证框架。
